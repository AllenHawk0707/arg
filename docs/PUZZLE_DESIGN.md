# PUZZLE_DESIGN — 谜题设计原理

## 原则（不可违反）

1. **每一道题都有唯一解，且解唯一**。如果发现歧义，立即收回。
2. **每一道题在解出后都能让玩家说"我现在知道为什么这一步要做这个了"**。没有"为谜题而谜题"。
3. **难度来源于信息差和思维跨越，不来源于繁琐操作**。不要让玩家手工算 `100000` 个 SHA-256。
4. **现实关联题的"现实性"必须是真实可达的**。如果指向某真实 PDF，必须先确认它在 2025 年仍可访问（如果不可访问，给出"考古路径"）。
5. **多线索交叉验证**。同一结论至少从两条独立路径可达。
6. **不要把密码藏在第 7 层隐写里**。信息嵌入应可被发现且可解。

## 谜题层级

| 层级 | 类型 | 示例 | 出现位置 |
|---|---|---|---|
| L1 | 古典密码 | 凯撒、维吉尼亚、Base64、Hex | 章节 0–1 |
| L2 | 现代密码 | AES-256、RSA、ECC | 章节 1–2 |
| L3 | 隐写 | 图像 LSB、音频频谱、零宽字符 | 章节 1–3 |
| L4 | 协议 | HTTP/IP/ARP 报头分析、PCAP、握手重放 | 章节 2–3 |
| L5 | 现实搜索 | 真实网站、PDF 段落、新闻报道 | 章节 1–2 |
| L6 | 现实物理 | 经纬度、街景、音频频段、星空 | 章节 0–3 |
| L7 | 元谜题 | 跨章节整合、博弈论、概率论 | 章节 3–99 |

## 平衡设计

- **章节 0 教学**：第一章中至少 2 题 L1 级（Base64 + Vigenère）。这两题必须给玩家充分训练再进入下一章。
- **章节 1–2 交替**：每章有 1–2 道 L3–L4 的"高光题"，提供跨章节整合。
- **章节 3 终局**：玩家必须独立选择"是否对暗号"——这是 ARG 中罕见的"玩家行动有后果"的设计。
- **章节 99 真相**：玩家到达这里时已经知道了 80% 的事实，最后的 20% 通过一段 4 分钟的音频独白揭示。

## 解谜工具箱

提供在 `src/puzzle/` 的 JS 工具：

- `cipher.js` — Caesar、Vigenère、AES-CBC（Web Crypto API）、Base64/Base32、Hex
- `stego.js` — 图像 LSB 提取、音频频谱 PNG 导出、零宽字符
- `qr.js` — 生成 QR 码（不含现实扫描的桥接）
- `search.js` — 模拟"打开浏览器搜索"的提示（不真实访问）
- `codec.js` — Morse、二进制、八进制、罗马数字

**实际加密/解密调用**：

```js
// 在浏览器控制台（F12 在命令行）
Edenfall.use('vigenere').decode('BALANCED', cipher); // → "HENRIETTE"
Edenfall.use('aes').decrypt(b64Ciphertext, 'PASSWORD');
Edenfall.use('base64').decode('aGVsbG8=');  // → "hello"
```

## 提示系统

- **不直接给提示**。给玩家**资源**。让玩家自己决定下一步。
- 资源例子：
  - 一段历史事件的真实录音（不直接说答案）
  - 一个真实地点的街景链接
  - 一段学术论文的相关章节

## 死胡同的处理

- 如果某条路径被证实无解（这是**会发生的**），在 `journal.md` 标注 `(dead end — confirmed 2025.xx.xx)`。
- 玩家对死胡同的质疑，**永远不要嘲讽**。承认错误，重新设计。

## 跨媒介

- **音频**：EF-7 的通讯日志应该有真实的"无线电噪声"质感。在 `assets/audio/transmissions/` 准备。
- **视频**：黑匣子（章节 2）应有一段 4 分钟的监控录像片段，带时间码。
- **文本**：所有文档都用 `Courier New` + 纸质纹理背景，模拟打印件。
- **图像**：SARAS 画（章节 1）应扫描原件。

## 谜题模板（JSON 规范）

每道题以 JSON 文件存放于 `puzzles/crypto/`、`puzzles/stego/`、`puzzles/code/`、`puzzles/meta/`：

```json
{
  "id": "puzzle-00-001",
  "chapter": "00_signal",
  "level": 1,
  "type": "base64",
  "title": "First Contact",
  "hints": [
    "看起来像乱码……但所有的乱码都有它的表。",
    "这是工业界最常用的编码之一（提示：邮件附件）。"
  ],
  "answer": "EDENFALL IS LISTENING",
  "answer_sha256": "<hash>",
  "next_puzzle": "puzzle-00-002",
  "spoiler": false
}
```

玩家通过 `Edenfall.verify('answer', 'puzzle-00-001')` 验证。`answer_sha256` 验证答案时不泄露答案本身。

## 防剧透机制

- 公开讨论/剧情梗概必须经 24 小时缓冲。
- 玩家提交答案用 SHA-256 哈希比对，不在客户端硬编码明文答案。
- 关键剧情文件加 `.enc` 扩展名（加密）。只有验证谜题后方可解锁。

## 测试与平衡

每个新谜题必须经过至少 3 人盲测：
- 1 人懂密码学
- 1 人不懂密码学但爱 ARG
- 1 人是完全新手

如果新手在 30 分钟内给出一致求助意见，重新设计。
